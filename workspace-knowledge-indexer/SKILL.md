# 工作空间知识索引器

## 概述

此技能将用户散落在历史对话、文档目录、下载文件夹中的知识与信息，结构化为一张可检索的「知识地图」。核心目标：让 AI 在未来每次对话中，能**瞬间定位到与当前任务相关的历史上下文**，避免重复询问、遗漏关键信息、或从头分析已处理过的问题。

本技能支持两种运行模式：

- **构建索引模式**（`build`）：全量扫描所有知识源，生成或更新结构化知识索引文件
- **智能检索模式**（`recall`）：基于当前任务描述，从已有索引中召回最相关的上下文片段

## 适用场景

**主动触发（用户明确请求）：**

- 「整理一下我的知识库」「建个索引」「梳理过往工作」「回顾项目文档」
- 「把历史对话整理一下」「把 Documents 里的文档归类一下」
- 「我之前做过一个 XX，帮我找找」
- 「更新知识索引」

**自动触发（无需用户请求，AI 自主判断）：**

- 当前任务涉及某个业务领域，但本地 `.workbuddy/memory/` 中缺少相关信息
- 用户提到"之前""上次""我们讨论过"等回溯性表述
- 用户开始一个可能与历史项目相关的新任务（如再次提到非洲公寓、抖音脚本等）
- 工作区中存在大量未分类的文档，需要建立结构化索引

## 知识源定义

本技能索引以下四类知识源：

### 知识源一：历史对话

通过 `conversation_search` 工具检索用户的历史对话记录。

**索引策略：**

1. 使用多组语义不同的查询词分批检索，每组查询聚焦一个业务领域或任务类型
2. 提取每条检索结果中的核心信息：对话 ID、主题、目的、关键实体、产出物、未完成事项
3. 按**业务领域**归类（而非按时间），每个领域下按时间倒序排列
4. 标记每条记录的状态：已完成 / 进行中 / 未完成

### 知识源二：本地文档目录

扫描用户的关键文档目录，建立文件级索引。

**扫描范围：**

| 目录 | 扫描深度 | 说明 |
|------|----------|------|
| `~/Desktop/` | 仅第一层 | 桌面文件通常为当前活跃项目 |
| `~/Documents/` | 仅第一层 | 主要工作文档存放地 |
| `~/Downloads/` | 最近 30 天修改的文件 | 临时下载但可能重要的文件 |
| `~/.workbuddy/skills/` | 仅目录名 | 已安装的自定义技能 |

**索引内容：**

- 文件/目录名
- 类型推断（基于扩展名：PDF、CSV、SQL、HTML、JSON、ZIP、图片等）
- 所属业务领域（通过文件名和目录名推断）
- 最后修改时间（仅 Downloads）

### 知识源三：工作区记忆

读取并整合已有的 `.workbuddy/memory/` 中的日志和笔记，作为索引的补充基础。

### 知识源四：技能与工具清单

列出用户已安装的自定义技能及其用途，作为能力索引。

## 工作流

### 模式一：构建索引（build）

按以下六步完成全量索引构建。

#### 第一步：扫描本地文档目录

使用 `Bash` 工具执行 `ls` 命令（`ls -la ~/Desktop/`、`ls -la ~/Documents/`、`ls -lt ~/Downloads/ | head -30`）获取文件列表。

对每个文件/目录：

1. 通过扩展名推断文件类型
2. 通过文件名和所在目录名推断所属业务领域
3. 记录到临时索引表中

**领域推断规则：**

- 含「非洲」「阿比让」「天鹅湖」「凤凰城」「公寓」「地块」「地产」「properties」「price」「location」→ `非洲房地产运营`
- 含「抖音」「douyin」「脚本」「海报」「poster」「内容」「营销」「短视频」「小红书」「xhs」「笔记」「种草」→ `内容营销`
- 含「公司」「营业执照」「DUNS」「投资」「会议纪要」「备案」→ `企业运营`
- 含「sql」「csv」「html」「代码」「test」「project」「superset」「automated_testing」→ `技术开发`
- 含「App Store」「Google Play」→ `应用商店上架`
- 其他无法推断的 → `未分类`

#### 第二步：检索历史对话

使用 `conversation_search` 工具，分多组查询词检索历史对话。

**推荐查询词组（覆盖主要业务领域）：**

```
组1: "非洲业务、房地产、公寓、出租、地块价格"
组2: "抖音、短视频脚本、内容策略、出海营销、海报"
组3: "技能开发、代码、SQL、数据分析、自动化"
组4: "公司运营、营业执照、邓白氏、App Store 上架"
组5: "报告撰写、PPT、文档整理、数据分析"
```

对每组查询结果：

1. 提取摘要中的核心信息
2. 按业务领域归类
3. 标记任务状态（根据摘要中的关键词：进行中/未完成/已完成）
4. 记录对话 ID 和更新时间

#### 第三步：读取工作区记忆

读取当前工作区和用户级别的记忆文件：

- `~/.workbuddy/MEMORY.md`（用户级长期记忆）
- `{workspace}/.workbuddy/memory/MEMORY.md`（项目级长期记忆）
- `{workspace}/.workbuddy/memory/` 下的日期日志文件（最近 10 个）

提取其中的关键决策、技术偏好、项目约定等信息。

#### 第四步：整合分类

将前三步收集的所有信息，按以下分类体系整合。

**分类体系定义见** `references/documents-taxonomy.md`。

每个分类下包含：

- **历史对话记录**：对话 ID + 主题 + 状态 + 关键实体
- **相关文档**：文件路径 + 类型 + 推断说明
- **关键决策与约定**：从记忆文件中提取的重要信息

#### 第五步：生成索引文件

将整合结果写入索引文件，存储位置：

```
{workspace}/.workbuddy/memory/KNOWLEDGE_INDEX.md
```

索引文件格式使用 Markdown，包含以下固定章节：

```markdown
# 工作知识索引

> 最后更新：{日期}
> 索引版本：v{N}
> 来源：历史对话 {N} 条 + 本地文档 {N} 项 + 记忆文件 {N} 个

## 一、业务领域概览

### 1.1 非洲房地产运营
（该领域的历史对话 + 文档 + 关键信息）

### 1.2 内容营销 / 抖音
...

### 1.3 企业运营
...

### 1.4 技术开发
...

## 二、未完成任务清单
（所有标记为"进行中"或"未完成"的历史对话任务）

## 三、已安装技能清单
（自定义技能列表及其用途）

## 四、文档快速导航
（按类型分组的文档路径索引）

## 五、关键决策与约定
（从记忆文件中提取的重要决策记录）
```

**写入规则：**

1. 使用 `Write` 工具创建或覆盖索引文件
2. 每次构建索引时版本号递增
3. 在索引文件头部标注最后更新时间和数据来源统计
4. 每个领域的条目按时间倒序排列（最近的在前）

#### 第六步：输出摘要报告

向用户输出一份简洁的索引构建摘要，包含：

- 扫描了多少条历史对话
- 索引了多少个本地文档
- 识别出哪些业务领域
- 发现了多少个未完成任务
- 索引文件的存储路径

### 模式二：智能检索（recall）

按以下四步完成上下文召回。

#### 第一步：解析当前任务

分析当前对话中用户正在做什么任务，提取以下信息：

1. **任务类型**：分析报告、脚本生成、代码开发、数据查询、文档整理等
2. **涉及领域**：非洲房地产、内容营销、企业运营、技术开发等
3. **涉及实体**：具体项目名（天鹅湖、凤凰城）、文件名、工具名等

#### 第二步：加载索引

读取 `{workspace}/.workbuddy/memory/KNOWLEDGE_INDEX.md`。

若索引文件不存在，向用户提示：

> 「知识索引尚未构建。是否现在执行一次全量索引构建？」

#### 第三步：匹配相关条目

根据第一步提取的任务信息，在索引中匹配：

1. **按领域匹配**：当前任务所属领域下的所有历史记录和文档
2. **按实体匹配**：索引中提到相同项目名/文件名的条目
3. **按类型匹配**：当前任务类型相似的历史任务

匹配结果按相关度排序，取最相关的 3-5 条。

#### 第四步：输出上下文摘要

将匹配到的条目整理为简洁的上下文摘要，格式：

```markdown
## 相关历史上下文

### 📂 相关项目/领域：{领域名}

**历史对话（{N} 条相关）：**
- [{日期}] {主题} — {状态} | 关键实体：{实体列表}

**相关文档：**
- `{文件路径}` — {类型}：{推断说明}

### ⚠️ 未完成任务
- [{领域}] {任务描述}（来自 {日期} 的对话）
```

**重要规则：**

- 检索结果仅作为**上下文参考**，不替代当前任务的实际执行
- 若检索发现存在**直接相关的未完成任务**，提醒用户：「您之前有一个相关的未完成任务，是否继续？」
- 输出要简洁，不超过 20 行，避免信息过载

## 输入输出约束

### 输入格式

**构建索引模式（build）：**

- 用户说「整理知识库」「建索引」「梳理工作」等，或 AI 自动判断需要构建
- 可选参数：指定扫描的目录范围、查询的时间范围

**智能检索模式（recall）：**

- 无需显式输入，AI 基于当前任务自动触发
- 检索关键词从当前对话的任务描述中提取

### 输出格式

**构建索引模式输出：**

1. 索引构建摘要（控制台输出，简洁列表）
2. 完整索引文件写入 `{workspace}/.workbuddy/memory/KNOWLEDGE_INDEX.md`

**智能检索模式输出：**

1. 上下文摘要（Markdown 格式，嵌入当前对话）
2. 不修改索引文件本身

## 索引维护策略

### 增量更新

索引不需要每次全量重建。在以下时机执行**增量更新**：

1. **完成重要任务后**：在任务完成时的记忆写入环节，同步更新索引中对应领域的条目
2. **用户主动请求**：用户说「更新索引」时执行
3. **索引过期检测**：若索引文件的最后更新时间超过 7 天，在下次智能检索时提醒用户

### 过期清理

- 超过 90 天的已完成任务记录，从索引中移入「历史归档」章节
- 超过 180 天的归档记录，从索引文件中删除（信息已沉淀到领域知识中）

## 边界情况处理

| 边界情况 | 处理策略 |
|----------|----------|
| 历史对话检索结果为空 | 仅索引本地文档和记忆文件，在摘要中注明「未检索到历史对话记录」 |
| 索引文件被意外删除 | 下次智能检索时提示用户重建，自动切换到构建索引模式 |
| 文档目录权限不足 | 跳过该目录，在摘要中注明「{目录名} 权限不足，已跳过」 |
| 文件名无法推断领域 | 归入「未分类」章节，不强行猜测 |
| 用户记忆文件为空或不存在 | 正常继续，索引中标注「暂无记忆文件数据」 |
| 索引文件过大（超过 500 行） | 启用分段存储，主索引仅保留摘要，详细索引按领域拆分为子文件 |
