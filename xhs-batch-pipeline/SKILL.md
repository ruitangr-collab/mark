# 小红书内容批量生产管线 v2.0

## 概述

本技能是 xhs-note-writer 的上层调度器。xhs-note-writer 解决"怎么写一篇笔记"，本技能解决"从哪取选题、怎么批量推进、怎么补真实背景"。

**v2.0 核心变更：全部内容以图文形式发布，不再制作视频。**

核心流程：**读策略日历 → 定位下一篇 → 补真实背景 → 撰写图文草稿 → 用户确认 → 入库索引**。

**关键规则：只有经用户确认的内容才进入管线正式目录。未确认的草稿存入 `待确认/`，不算有效资产。**

触发条件：
- 用户说"继续写""批量出笔记""从日历取选题""帮我出下一篇""跑日历"
- 用户说"/xhs-batch"
- 用户说"把剩下的日历全跑完""今天写几篇"

## 前置依赖

### 统一管线目录

所有小红书内容统一存放在以下目录（固定路径，不受 workspace 切换影响）：

```
/Users/goterra/WorkBuddy/小红书内容管线/
├── INDEX.md              ← 主索引（入口）
├── 策略方案/             ← 策略文档（v2.0）
├── 图文笔记/             ← 【已确认】图文笔记 .md（正式资产）
├── 视频脚本/             ← 【历史资产】旧版视频（不再新增）
├── 待确认/               ← 【草稿】等待用户确认的内容
├── 日历与索引/           ← 进度总表
└── 素材与参考/           ← 门店实景图、合同样本等
```

**「待确认」与正式目录的区别：**
- `待确认/`：刚写完，用户还没看过。不算进度完成，不更新索引。
- `图文笔记/`：用户已确认。算进度完成，索引已更新。
- `视频脚本/`：旧版策略的历史资产（Day 2、Day 5），**不再新增视频内容**。
- 用户说"没问题"、"确认"、"可以"、"过" → 从待确认移动到 `图文笔记/`。
- 用户说"改一下XX" → 修改后重新确认。
- 用户说"不要了""换一个" → 从待确认删除，重新写。

执行前必须确认以下文件存在，缺任何一项都先问用户要：

| 文件 | 路径 | 内容 | 必要性 |
|------|------|------|--------|
| 策略方案文档 | `管线根目录/策略方案/小红书运营策略方案_非洲中介门店店长.md` | 选题日历、定位分析、人设定义（v2.0） | 必须 |
| 主索引 | `管线根目录/INDEX.md` | 进度总览、人设规则、调用指南（v2.0） | 推荐 |
| 已完成笔记 | `管线根目录/图文笔记/` | 用于判断进度到哪一天、保持风格一致 | 必须（首次可以为空） |

管线根目录固定为 `/Users/goterra/WorkBuddy/小红书内容管线/`，首次运行自动读取，无需询问用户。

## 工作流程

### Phase 1：定位当前进度

1. **先检查待确认目录**：
   - `ls /Users/goterra/WorkBuddy/小红书内容管线/待确认/`
   - 如果有文件 → 提醒用户：「上次有几个草稿还没确认，要先处理吗？」让用户决定是确认入库还是跳过重写
2. 列出已确认的笔记：
   - 图文笔记：`ls /Users/goterra/WorkBuddy/小红书内容管线/图文笔记/`
3. 加载策略日历（第四节「30天内容日历 v2.0」），对照已确认的 Day 编号确定进度
4. 确定下一篇是 Day N（N = 最后一个已确认 Day + 1，跳过视频旧版 Day）
5. 如果用户指定了数量（如"写3篇"），则连续取 Day N, N+1, N+2
6. 优先读取 `INDEX.md` 快速获取进度，不必每次都重新扫描文件

输出示例：`当前进度：Day 1-5 已完成（Day 2、Day 5 为旧版视频）。本次将撰写 Day 6-7，共 2 篇图文笔记。`

### Phase 2：补充真实背景

写之前，必须从以下来源补充人设和背景信息，**不要问用户重复要**：

1. **策略方案文档（v2.0）**：人设定义、定位、四大支柱、50个选题库
2. **历史对话**（conversation_search）：用户之前提到的真实经历、细节、偏好
3. **工作区记忆文件**（.workbuddy/memory/）：之前记录的关键上下文
4. **已完成的图文笔记**：保持风格和事实一致性

需要补充的背景维度：
- 人设核心信息（地点、职业、时长、独特经历）
- 当天选题涉及的具体行业知识和真实细节（地产交易/员工管理/客户族群/合规）
- 之前笔记中已建立的人设元素（避免矛盾）

**关键规则：不要向用户提问。能从文档和记忆中找到的信息就自己找，找不到的合理推断，只有遇到无法推断的硬事实才问。**

### Phase 3：撰写图文笔记（唯一格式）

调用 xhs-note-writer 的框架执行：

1. **选题分析**：这个选题的受众是谁？他们关心什么？情绪触发点在哪？
2. **确定钩子类型**（5选1）：
   - 数字冲击型（"月租多少，我拆了10单"）
   - 反常识型（"不是你想的那样"）
   - 共鸣吐槽型（"崩溃瞬间"）
   - 干货清单型（"启动资金拆解"）
   - 悬念揭秘型（"真相是…"）
3. **标题生成**：3个候选标题，用小红书爆款公式（v2.0）
4. **正文撰写**（800-1500字，5-6段结构）：
   - 钩子段：第一句话就要抓住
   - 事实段：真实细节，不是泛泛而谈
   - 冲突段：转折、反转、认知落差
   - 干货段：可操作的信息（如有）
   - 收尾段：互动引导 + 追补话术
5. **配图方案**：6-12张，门店实景/合同样本（打码）/本地员工工作照/客户签约现场
6. **去 AI 味处理**（逐条检查）：
   - ❌ 不用"让我们一起"、"不难发现"、"值得注意的是"、"总而言之"
   - ❌ 不用排比三段式、不写"其实…本质上…"的总结句
   - ❌ 不用表情符号堆砌（最多3个，放在关键位置）
   - ✅ 用口语化短句、真实细节、不完美的表达
   - ✅ 允许带一点方言/外语词汇（如法语/西非法语词汇增强真实感）
7. **标签**：5-8个，含垂类标签（非洲地产/非洲中介）+ 流量标签
8. **封面方案**：3选1，每个有主标题+副标题+画面描述（门店实景优先）

### Phase 4：交付草稿（待确认）

1. 文件命名规范：`笔记_{Day编号}_{选题关键词}.md`
   - 示例：`笔记_Day6_阿比让3居室月租拆解.md`
2. **写入草稿位置**：
   - 写入 `待确认/` 子目录：`/Users/goterra/WorkBuddy/小红书内容管线/待确认/`
   - 同时写入当前工作区（用户可即时查看）
3. **呈现给用户确认**：
   - 简洁列出每篇草稿的：Day编号 / 内容支柱 / 选题 / 核心亮点
   - 明确说出「请确认后再入库，确认后我会更新索引」
   - **此时不更新索引，不标记进度完成**
4. **等待用户反馈**：
   - 用户说"没问题""确认""可以""过""行" → 进入 Phase 4B（确认入库）
   - 用户说"改一下XX" → 修改后重新呈现
   - 用户说"不要了""换一个" → 从待确认删除，返回 Phase 1 重写

### Phase 4B：确认入库

仅在用户明确确认后执行：

1. **移动文件**：从 `待确认/` → `图文笔记/`
2. **更新所有索引**：
   - 更新 `日历与索引/内容日历索引.md`：标记新 Day 为 ✅，更新支柱覆盖统计
   - 更新 `INDEX.md`：同步日历进度表、内容支柱覆盖统计
3. **更新工作区记忆**：更新 `.workbuddy/memory/MEMORY.md` 中的当前进度
4. **清理草稿**：从当前工作区删除草稿文件（管线已有正式版本）
5. 向用户报告：入库完成，当前进度更新到 Day N，附索引链接

### Phase 5：批量控制

如果用户要批量（"帮我出3篇"）：
1. 用 TaskCreate 创建任务列表，每篇一个任务
2. 依次执行 Phase 1-3，每完成一篇标记 completed
3. 全部草稿完成后，统一进入 Phase 4（呈现待确认）
4. 用户批量确认后，统一进入 Phase 4B（入库索引）

如果用户要"跑完日历"：
1. 计算剩余篇数
2. 先确认数量（超过10篇时分批）
3. 每批 3-5 篇写完后进入确认环节，确认后再推进下一批

## 人设一致性规则（v2.0）

跨多篇写作时必须遵守：

- **事实一致**：已发布的笔记中提到的数字、地名、时间线不能矛盾
- **语气一致**：保持同一个人说话的风格（口语化、接地气、不端着）
- **角色一致**：每次出现的"我"是同一个人——同一个地点、同一个职业阶段
- **渐进披露**：不要在第一篇就把所有背景交代完。个人信息分批释放，像真人一样逐步展示。
- **v2.0 新增**：地产门店实战内容必须有具体细节（交易金额区间、员工管理具体场景、客户族群具体行为），不能泛泛而谈

## 质量标准

每篇交付前自检：

- [ ] 标题有点击欲（不是标题党，是有信息量的钩子）
- [ ] 第一段3秒内抓住读者
- [ ] 有至少1个真实细节是 AI 编不出来的（具体金额、地名、对话片段）

- [ ] 标签覆盖垂类（非洲地产/中介）+ 流量标签
- [ ] 配图方案可直接执行（门店实景/合同打码/工作照）
- [ ] 内容支柱归属正确（地产实战/跨文化/出海创业/门店生活）
