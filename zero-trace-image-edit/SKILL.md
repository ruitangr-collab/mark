## 一、什么时候用它

需求方说："这张图我挺喜欢，但**把左边那个口袋换成另一张图那样的**"
——传统做法要么整张重做、要么 PS 抠半天。本技能把这句话**当场**变成 4 个产物：

1. **改图效果图**（真实生成图；本机 GPU 或公开渠道自适应，**绝不模拟**）
2. **闸门①前置确认表**（Word，9 项逐项勾选，签名①锁定意图）
3. **闸门②量化点检报告**（JSON，机测 ΔE/角度 + 人工复核项，PASS/FAIL/NOT_RUN）
4. **双签水印最终确认表**（Word，签①+签②都采「登录用户名+系统时间戳+责任勾选」）

### 四类改法，覆盖所有"动图"需求

| 改法 | 一句话说法 | 例子（服装） | 例子（通用） |
|---|---|---|---|
| **移除** | "把这个东西拿掉" | 拆掉两侧口袋 | 去掉路人 / 杂物 / 瑕疵 / 水印 |
| **替换** | "把这个换成那个" | 把原贴袋换成斜插袋 | 换家具 / 换轮毂 / 换背景物 |
| **添加** | "这里加一个" | 裤子上加个工装袋 | 加元素 / 加软装 / 加标识 |
| **改色** | "这个颜色改了" | 缝线改成同色 | 改商品配色 / 改车身颜色 |

### 核心差异：只改你指的地方，其余零改动

一般改图工具是"整张重画"——改完背景、光线、旁边的东西全变了，没法交付。
本技能走的是 **生成式造形 + 像素法校色 的组合拳**：
生成式负责"把形状做出来"，像素法负责"把颜色校回原样"。

| 指标 | 实测 |
|---|---|
| 纯色改色场景 · 目标区域外保真 | **99.89%** |
| 结构改造场景 · 整图色偏（未修正 → 曲线校色后） | −17 → **4.7 以内** |
| 空间均匀性 · 分块色差 | ≤ 6（无拼接块痕迹） |

**客户看不出你改过哪里 —— 这才是能交付的东西。**

## 二、出图通道自适应（2026-09-04 铁律，代码硬编码）

```
run_pipeline --execute 时自动执行 env_check 真实探测
（nvidia-smi → torch.cuda → PowerShell CIM 三级兜底，可识别 VDI/Citrix 下 nvidia-smi 失效）

🟢 LOCAL_FOOOCUS      本机 GPU + 后端就绪 → 本地出图（图不出厂、零按次付费，首选）
🔵 PUBLIC_OPENSOURCE  本地不可用（没装/没条件装 GPU 环境）→ 自动改走公开开源渠道
                      出真图，明确告知「图会出网」；同时提示如何装回本地
🔴 BLOCKED            仅当使用者选 --no-public（隐私模式）且本地不可用 → 禁止出图
```

- **不卡死**：没 GPU 的使用者也能拿到真图——技能自主走开源渠道完成任务，不把人挡在半路。
- **必告知**：走公开渠道时输出 📢 告知（图会出网），涉密客户图请用 `--no-public` + 本地环境。
- **绝不假图**：任何通道、任何失败场景，都严禁模拟图/占位图/示意图冒充交付。这是红线。

## 三、流水线 S0–S8（每个环节都有出口自检）

| 顺序 | 环节 | 自检规则（不过则停） |
|---|---|---|
| **S0** | 素材受理 + 环境探测 | 短边≥1024px；摆位底图必须是**平铺图/线稿**；真实探测 GPU/依赖/后端 |
| **S1** | **镜像归一化** | 锁定 wearer_frame（哪边是穿衣人的右）；多线索判不准→ 弹「图里哪边是穿衣人右手」一次点击 |
| **S2** | 部件提取 | B 轮廓闭合、参数在合理域；失败→ 要 B 局部大图或手绘轮廓兜底 |
| **S3** | 意图解析 | 9 项槽位无空缺；歧义词强制追问；置信低→ 转 UI 点选 |
| **S4** | **闸门① 9 项前置确认** | 9/9 显式勾满；**位置必须来自图上摆位动作**（不接受文字描述）；派生一致性（选料=B → 必触发纹理对齐） |
| **S5** | **签名①（意图）** | 登录用户名+责任勾+时间戳；签后**冻结 items 哈希**；改任一项即作废重走 S4+S5 |
| **S6** | 生成出图（自适应） | 通道按第二节路由；落点偏移 ≤ 容差；部件朝向未左右翻转；失败自动重跑上限 3 |
| **S7** | **闸门② 量化点检** | 机测：ΔE<3、角度差≤3°；人工复核：尺寸±5%、协调比≤40%、形状/位置/缝线；任一 FAIL=整体 FAIL；缺数据=NOT_RUN=**禁止签②** |
| **S8** | **签名②（验收）→ 封包** | 交付三件套：改图+确认表+点检报告；缺件或无双签水印=禁止发出 |

## 四、闸门① 9 项前置确认（执行前必须 9/9 显式确认）

| # | 主题 | 确认点（要点） |
|---|---|---|
| ① | 运行环境 | 本地 GPU（推荐）/ 公开开源渠道兜底（图出网）/ 隐私模式 --no-public |
| ② | 颜色（材质×颜色 **3×3 矩阵**） | 材质来源 {A 同材质, B 保持, 新指定} × 色来源 {A 同色, B 保持, 新指定} = 9 格点选 |
| ③ | 纹理方向 | 完全连续（显微镜级，慢） / 近似对齐（快）；**选「料=B」必触发对齐** |
| ④ | 人话转译 | LLM 解析 / UI 点选（拿不准走点选兜底） |
| ⑤ | 协调性容差 | 部件宽度占部位 ≤ __%（默认 40%）告警+出 3 备选；生成前红蓝框预览 |
| ⑥ | 形状（**子属性×来源**） | 形状 / 轮廓（倾斜角） / 圆角 R / 附加结构（宽占比+距主体 cm） / 铆钉（颗数+间距） / 描边型；**朝向锁部件开口朝上、禁翻转** |
| ⑦ | 尺寸 | 取 B 原尺寸 / 按 A 比例缩 / 新指定（__×__cm） |
| ⑧ | 位置（**图上直摆**，**取消文字确认**） | 视图 前/后/侧 + 左/右（实物参照）；图上拖放+1cm 网格+方向键微挪；**回读人话仅存档**；可勾「镜像复制到实物左区」 |
| ⑨ | 边缘/接缝（**子属性×来源**） | 线色（色来源）/ 线型（单/双线）/ 线宽（mm）/ 效果（平整/做旧/新） |

**位置这一项的硬约束（v2 修掉的镜像 bug）**：
任何原图（平铺拍、模特正面、背影）进来，系统先做一次「左右→实物参照坐标」的归一化。内部只存 wearer_frame 坐标，确认回译也**只输出实物参照坐标**——「图片右」这个词不出现在确认环节，从结构上消灭镜像错误。

## 五、闸门② 9 项量化点检（默认容差）

| # | 检查项 | 量化方法 | 默认容差 | 实测方式 |
|---|---|---|---|---|
| 1 | 无外部依赖 | 通道核验（本地 0 外联 / 公开渠道=已授权并告知） | 未授权 0 外联 | 机测 |
| 2 | 颜色 ΔE | 部件区 vs 周边同材质环带 ΔE76（同材质同色时） | ΔE < 3 | 机测 |
| 3 | 纹理方向 | 部件区 vs 环带 结构张量主角度（同材质时） | 角度差 ≤ 3° | 机测 |
| 4 | 人话转译 | 抽测 N 条真实人话指令 vs 实际出图 | 一致率 100% | 人工 |
| 5 | 协调性 | 部件宽度占部位比例 | ≤ 40% | 人工 |
| 6 | 形状 | 关键点（圆角 R / 盖距 / 铆钉位） | ±5% | 人工 |
| 7 | 尺寸 | 实测长宽 vs 确认 cm | ±5% | 人工 |
| 8 | 位置 | 落点偏移（红框目检/检测） | ≤ 0.5cm | 人工 |
| 9 | 边缘处理 | 描边 ΔE + 线宽/线数 | ΔE<3, ±0.3mm | 人工 |

**铁律**：缺数据 = NOT_RUN = 不能签②（不是跳过、更不是假 PASS）。机测项由 `--ingest` 自动回填；人工项出图后由使用者/AI 目检，把 measured 改成实测值、verdict 改成 PASS/FAIL 并在 basis 注明依据，然后才走签②。

## 八、出图引擎可插拔架构（v3.0.0 新增，v3.1.0 组合拳，v3.2.0 移除打法，v3.3.0 双动作/位置锚点，v3.4.0 曲线校色）

v2 只有三条通道（LOCAL/PUBLIC/BLOCKED），v3 升级为**6 引擎注册表 + 分级路由 + 自动降级**。

### 8.1 引擎登记表（`gate/engine_registry.py`）

| 引擎 | 类型 | 多参考图 | 画幅跟随 | 水印 | 凭据 | 质量档 |
|---|---|---|---|---|---|---|
| `seedream` | 外部API | ✅ | ✅ native | 无 | `ARK_API_KEY` | 1 |
| `kling` | 外部API | ✅ | ✅ | 无 | 各家 Key | 2 |
| `nanobanana` | 外部API | ✅ | ✅ | 无 | 各家 Key | 2 |
| `qwen-image-edit` | 外部API | ✅ | ✅ | 无 | `DASHSCOPE_API_KEY` | 3 |
| `fdplus` | 平台内置 | — | ❌ 锁1:1 | ⛔ WORKBUDDY | 零配置 | 4 |
| `local-fooocus` | 本机 | ✅ | ✅ | 无 | 零配置 | 5 |

**三条设计原则**（2026-09-11 用户决策）：
1. **默认零配置可跑** —— 不填 Key 不报错，上架版护城河
2. **引擎可插拔可降级** —— 主力挂了自动切备用，绝不卡死
3. **数据分级路由** —— 涉密客户图禁出网（`public` / `client` / `secret` 三档）

> ⚠ **凭据来源必须同源**（v3.4 修复）：方舟系的 `ARK_API_KEY` 读取顺序为
> **环境变量 → `~/.workbuddy/ark_config.json`** 两处。
> `engine_registry.has_credential()` 与 `ark_engine.load_credential()` **必须读同一份来源** ——
> 曾因注册表只查环境变量、不查配置文件，导致已落盘 Key 的机器上仍被判"缺凭据"，
> `choose_engine()` 每次任务都**错误降级**到低质量引擎。
> **自检法**：`ark_engine.py --check` 与 `engine_registry.py` 的就绪结论不一致 = 判定分叉，立即修。

### 8.2 ★ 引擎选择铁律：按**任务类型**选，不按引擎强弱选

| 任务类型 | 首选通道 | 理由 |

### 8.5 传统像素法（`gate/pixel_recolor.py`）

```bash
# 自动识别撞色缝线并改为大身同色
python gate/pixel_recolor.py --src A.jpg --out B.png --auto-thread --json report.json

# 指定源色/目标色
python gate/pixel_recolor.py --src A.jpg --out B.png \
    --from-color 192,180,163 --to-color 122,124,134 --tol 40
```

**实现要点（都是踩坑换来的）**：
- 检出阈值用**实测色值校准**：撞色缝线 `R-B>25 & R>90`
  （最初用 Lab a/b 阈值误判 28.3%，把大身算进去了）
- ⚠ **必须做连通域背景剔除**：木地板本身 R-B 也可能 >25，会被误判成缝线。
  实测某次 2451 个候选像素中 **98% 都在木地板上**，
  必须用「邻域主体占比 ≥0.45」把背景簇剔掉，否则会改到地板。
- 目标色取样**不能从环带取**：缝线像素分散 11 处，最大一簇在木地板区域
  → 正确做法：在**画面中央统计"偏蓝且亮度<150"的主体材质像素**
- 替换时保留原有明暗起伏（亮度比例映射），避免改出"死色块"

### 8.6 ★ 组合拳流水线（`gate/hybrid_pipeline.py`）

**这是 v3.1 最重要的工作流，解决"生成式色偏"这个交付级难题。**

**问题**：Seedream 能生成新结构（口袋/部件），但会给整图带来**均匀色偏**
（实测大身亮度 −20 ~ −30），交付客户时颜色对不上原款。

**解决**：让两个引擎**分工协作** ——
- Seedream 负责"**造形状**"（像素法做不到）
- 传统像素法负责"**校颜色**"（Seedream 做不好）

```bash
python gate/hybrid_pipeline.py --orig A.jpg --gen seedream_out.jpg --out fixed.jpg \
    --exclude 0.30,0.62,0.10,0.48 --json report.json
#           ↑ 排除新增部件区（y0,y1,x0,x1 画面比例），避免把新口袋算进色偏基准
#           ⚠ 顺序是 y0,y1,x0,x1（不是 x0,y0,x1,y1），写反会静默失效（脚本已加校验）
```

**实测效果**：大身亮度差 **−20 → −3**，口袋完整保留，3×3 分块偏差 ≤4。

#### ★ 校色模式二选一：`--mode curve`（默认，推荐） / `--mode shift`（旧法）

> **v3.4 重大升级**：实测发现 Seedream 的色偏**不是均匀加减，而是非线性压暗**
> （暗部压得多、亮部压得少）。因此"整图加同一个常数"必然**只能对齐一头**。

| 模式 | 原理 | 实测（PG-005 深灰裤） |
|---|---|---|
| `--mode shift`（旧） | 整图加减**一个常数** | 裤身 −0.1 ✅ 但**腰头 +17.3、背景 +13.8** ❌ |
| **`--mode curve`（新，默认）** | 按**像素亮度分箱**查表偏移 | **最大区域偏差 4.7** ✅ 全区域通吃 |

**为什么 curve 不会产生拼接块**：它的修正量**只取决于像素亮度**，
同一亮度的像素修正量完全相同 —— 是**空间均匀**的，与"分块映射"（按坐标分块）
有本质区别。分块会出矩形块，曲线不会。

**实测对照（同一张图、同一任务）**：

| 区域 | 未修正 | 常数偏移 | **曲线匹配** |
|---|---|---|---|
| 口袋位左 | −10.2 | −0.1 | +1.7 |
| 左裤腿 | −10.3 | −0.2 | +0.3 |
| 裤身中部 | −2.1 | +7.6 | **−4.7** |
| 腰头带 | +7.4 | **+17.3** | **+2.3** |
| 背景地毯 | +3.8 | **+13.8** | **+0.6** |
| 裤脚 | −3.2 | +6.8 | **−0.4** |
| **最大偏差** | 10.3 | **17.3** | **4.7** |

> **曲线实现要点**（`gate/tone_match.py`）：
> ① 按生成图亮度分箱（默认 28 箱），每箱统计 gen→orig 的逐通道均值差
> ② 滑动平均平滑（避免箱间跳变产生色带）
> ③ 应用时按像素亮度**线性插值**查表，再减去偏移
> ④ **取样掩膜收紧到衣身主体**（中央区域 + 中性色）—— 让背景像素混入取样会拉偏曲线

> ⚠ **关键教训：不要用分块/矩形的逐通道 mean-std 映射！**
> 曾按 3×3 网格分块做线性映射，结果在大身产生**可见的矩形拼接块**
> （因为部件 mask 是矩形，各块映射参数不同）。
> 正确做法：Seedream 的漂移是**全局均匀**的，只需算一个**全局色偏向量**，
> 整图统一平移补偿 —— 空间均匀，零拼接痕迹。

### 8.7 ★★ 移除部件专用打法（v3.2 新增，2026-09-11 PG-003 实测）

**加部件和拆部件，打法完全不同。** 加部件看"改了多少"，拆部件看"平不平"。

#### ① 提示词必须用**正向句式**，否定句式对 Seedream 无效

实测对比（同一张白裙子、同一任务"移除两侧口袋"）：

| 轮次 | 提示词写法 | 口部件区改动率 | 平整度 |
|---|---|---|---|
| v1 | "Remove BOTH pockets / **no** seam lines / **no** shadows" | 12.1% | 差 |
| v2 | "The front is **one single continuous uninterrupted panel** of smooth fabric" | **22.4%** | **PASS（0.49~0.59×）** |

> **规律**：Seedream 把"no X"理解成"这里有个 X"，越强调越保留。
> **正确做法**：把目标状态**正向描述成一个具体物件** ——
> 不说"不要口袋线"，说"**前片是一整块连续的平整材质**"。

**移除部件提示词模板（直接抄）**：
```
The <garment> front is ONE SINGLE CONTINUOUS uninterrupted panel of <fabric>,
stretching from the <top> all the way down to the <bottom>.
The left area and the right area are both completely plain flat continuous fabric,
with no vertical seam line, no panel boundary, no divider line, no <removed part> outline.
The fabric surface flows as one unbroken smooth plane across the whole front,
showing only soft natural folds. Keep <腰头/纽扣/拉链> and the background exactly as the original.
```

#### ② 验收判据：用**平整度（边缘强度下降）**，不是"改动率"

> ⚠ **踩坑记录**：PG-003 首版用"改动率 ≥85%"判，结果假 FAIL（实测 10%）。
> 原因：口袋分两类像素 —— **缝线/袋盖（细线，占比小）** 与
> **部件本体平面（占比大，移除后≈周围裙面，差值极小）**。
> 移动平均一看"改动率低"，但缝线其实已经全没了。

**正确判据：口袋本体边缘强度 → 是否降到"干净裙面"水平**

| 部位 | 边缘强度 原→出图 | 相对干净裙面 | 判定 |
|---|---|---|---|
| 左口袋本体 | 2.56 → **1.37** | **0.59×** | PASS |
| 右口袋本体 | 2.98 → **1.13** | **0.49×** | PASS |
| 对照·干净裙面 | 2.06 → 2.31 | 1.00× | 基准 |

**判据**：出图边缘强度 / 干净裙面边缘强度 **≤ 2.5 → PASS**（越小越平）。

#### ③ 必须排除**衣物固有结构线**，否则误判为"残留"

> ⚠ **PG-003 踩坑**：检测出"残留纵线 156%"，一度以为 Seedream 没做干净。
> 放大目检后确认：那是**裙子的侧缝**（从腰头贯到下摆的固有结构线），
> 口袋只是缝在侧缝旁边 —— Seedream **保留侧缝是正确的**，不是残留。
>
> **教训**：报"残留"前必须先放大目检，
> 区分「被移除部件的轮廓」vs「衣物固有结构线（侧缝/公主线/腰省）」。
> 纯数值检测会把结构线算成残留，导致误判 FAIL。

#### ④ 移除任务的三段式闭环
```
Seedream 正向提示词出图  →  平整度点检（边缘强度比）  →  组合拳校色（8.6）
       ↓                            ↓                          ↓
  造出"没有该部件"的形态      证明部件真没了            修回整图色偏（−4.3→−0）
```

### 8.8 ★★ 双动作与位置锚点（v3.3 新增，2026-09-11 PG-004 实测）

**"拆一处 + 加一处"同时做，比单动作难一个量级。** 记住三条：

#### ① 位置类需求：必须用**图上可见参照物做锚点**，禁用模糊空间词

> ⚠ **PG-004 实测**：v1 提示词写 "on the upper front area"（前片上方）→
> 出图口袋落到**大腿中部**，位置偏低，客户要的"原袋位置"没对上。
> v2 改成锚点式描述后**一次修正到位**。

**锚点式写法（直接抄）**：
```
POSITION (critical): each new pocket occupies EXACTLY the same location as the
<pocket> it replaces. Looking at Image 1, the existing <部件> has its top edge
starting immediately at the bottom edge of the <腰带/领口/袖窿>, extending down to
<可见参照物>. The new <部件> sits in that same footprint, top edge flush against
the <腰带缝>. It is NOT on the <错误位置1> and NOT on the <错误位置2>.
```

**可当锚点的参照物**：腰头缝、领口、袖窿、门襟、侧缝、原部件轮廓、下摆。
**禁用的模糊词**：`upper / lower / middle front`、`on the thigh`、`around the hip`
—— 模型对这些词的空间理解与人类不一致。

#### ② 色偏修正的取舍：全局向量**只能对齐一头**，优先保主体

> ⚠ **PG-004 实测**：Seedream 对**主体与背景的漂移幅度不一致**
> （裤身 −9.1，全图含背景仅 −3.4）。组合拳用单一全局向量修正后：
> **裤身 −9.1 → +1.5 ✅**，但**背景被连带提亮 −3.4 → +7.2 ⚠️**。

| 取舍 | 适用 |
|---|---|
| **对齐主体**（推荐） | 客户看的是衣服；背景是拍摄环境，客户通常不在意 |
| 对齐全图 | 只有背景也是交付内容时才这么做 |

**做法**：交付时**同时给两个版本**（修正版 / 未修正版），并在报告里如实写明差异，让使用者选。

#### ③ "同材质同色"检测：基准区必须与目标区**光照相当**

> ⚠ **PG-004 踩坑**：脚本报"新袋 vs 大身色差 81"（假警报）。
> 根因：大身基准取在**裤腿中段的阴影区**，新袋在**受光正面** ——
> 同一块布，受光处与阴影处本来就能差 80 个色阶。
>
> **教训**：算同材质同色时，基准区必须与目标区**光照条件相当**（同在受光面或同在阴影面），
> 不能跨明暗交界取样。否则会误报"颜色不对"。

#### ④ 多动作任务迭代节奏
```
第一轮：把结构写对（形状/数量/关系）→ 位置/细节可能不准
第二轮：用锚点法修正位置 → 位置到位，此时色偏仍在
第三轮：组合拳校色 → 成品
```

### 8.9 ★★ 斜插袋嫁接 + 曲线校色（v3.4 新增，2026-09-11 PG-005 实测）

**本次任务**：A 图（深灰束脚裤）前片左右两个圆角贴袋 → 移除；B 图（卡其工装裤）**斜插袋（slanted welt pocket，斜向开口+唇边镶条+描边）** → 嫁接至同位置。

#### ① 好消息：**锚点法写到位，斜插袋一轮出图即成**

按 8.8 的锚点式模板**第一轮就写死位置**（不再走"先跑一版看位置"的老路）：
```
POSITION (critical): the new slanted welt pockets occupy EXACTLY the same footprint
as the rounded patch pockets they replace — top edge flush against the bottom edge
of the elastic waistband, extending down to the hip line. NOT lower, NOT on the thigh.
```
结果：**结构 + 位置一轮全对**，没有出现 PG-004 那种"口袋掉到大腿中部"的返工。
> **结论**：位置锚点描述法**可复用**，多动作任务的迭代节奏可以压缩到
> **两轮**（结构+位置同行 → 校色一轮）。

#### ② 斜插袋（welt）的提示词要点

斜插袋是**开口式**部件（不是贴片），要写清"是开口不是贴袋"：

```
each pocket is a SLANTED WELT POCKET: a diagonal opening cut into the front panel,
finished with a narrow self-fabric lip (welt) and a single row of topstitching along
its length. It is an OPENING in the fabric, NOT a patch sewn on top. Same dark grey
fabric as the pants, blending seamlessly.
```
> 关键词：`SLANTED WELT POCKET` / `diagonal opening cut into the panel` /
> `narrow self-fabric lip` / **`an OPENING, NOT a patch sewn on top`**。
> 最后那句是关键——不写清楚模型容易做成"贴一块斜的布上去"。

#### ③ 校色：常数偏移的**结构性缺陷**被本次彻底暴露

> ⚠ **PG-004 的 `--exclude` 参数我写反了**（写成 `y0>y1`、`x0>x1`），
> 触发静默失效 → 排除框为空 → 新口袋被算进色偏基准 → 校色被带偏。
> **已在 `hybrid_pipeline.py` 加参数顺序校验，写反直接报错拦截。**

同一张图、同一任务，三种校色对比（深灰裤，比白裙更吃亮度）：

| 区域 | 未修正 | 常数偏移 `--mode shift` | **亮度曲线 `--mode curve`** |
|---|---|---|---|
| 口袋位左 | −10.2 | −0.1 | +1.7 |
| 左裤腿 | −10.3 | −0.2 | +0.3 |
| 裤身中部 | −2.1 | +7.6 | **−4.7** |
| 腰头带 | +7.4 | **+17.3** | **+2.3** |
| 背景地毯 | +3.8 | **+13.8** | **+0.6** |
| 裤脚 | −3.2 | +6.8 | **−0.4** |
| **最大偏差** | 10.3 | **17.3** | **4.7** |

**根因**：Seedream 的色偏是**非线性压暗**（暗部压得多、亮部压得少），
所以"整图加同一个常数"必然**只能对齐一头** —— 修了暗部，亮部就过头。
曲线匹配按**像素亮度**查表，同一亮度修正量相同（**空间均匀，不是分块**），因此能全区域通吃。

**默认已切到 `--mode curve`**。旧行为保留：加 `--mode shift` 可回退。

#### ④ 曲线校色的两条实现关键（否则会翻车）

| 要点 | 说明 |
|---|---|
| **取样掩膜要收紧到衣身主体** | 让背景像素混入取样会**拉偏曲线**（背景与衣身漂移幅度不同）→ 加中央区域约束 |
| **必须做箱间平滑 + 线性插值** | 不做平滑会出现**分箱色带**（28 箱箱间跳变肉眼可见）→ 滑动平均 + 插值 |

> 实现见 `gate/tone_match.py`：`build_tone_curve(orig, gen, mask, bins=28, smooth=2)`
> → `apply_tone_curve(gen, centers, offsets)`。
> 实测：取样掩膜收紧后，**最大区域偏差从 6.8 进一步降到 4.1**。

### 8.10 ★★ 三图同改 / 级联嫁接（v4.1.0 新增，2026-09-14 猪→马→牛实测）

**一句话**：一次改图可以分别指定「形状来自 B、材质来自 C、颜色来自 A」，
也可以把上一步的输出作为下一步的 B，形成**级联**。

**最直观的例子（猪嘴 + 马脸 + 牛身）**：
想象你手上有三张图——一张**牛**的全身照、一张**马脸**（马的头部）特写、一张**猪嘴**特写。
- Stage 1：把猪嘴嫁到马脸上 → 得到一张「长着猪鼻子的马脸」；
- Stage 2：把这张「猪嘴马脸」整体嫁到牛身上 → 得到一只「长着猪鼻马脸的牛」。
两步各跑一次、各签一次确认书，最终产出就是「猪嘴 + 马脸 + 牛身」的级联合成图。
下面用这张真实跑通的测试，把来源路由、诚实拦截、解药一次讲清。

#### ① 来源路由表

确认书 `items.sources` 三个字段独立路由：

| 字段 | 可取值 | 含义 |
|---|---|---|
| `shape_from` | A / B / C / new | 部件轮廓/结构来自哪张图 |
| `fabric_from` | A / B / C / new | 材质/纹理来自哪张图 |
| `color_from` | A / B / C / new | 颜色来自哪张图 |

默认双图场景：`shape_from=B, fabric_from=B, color_from=B`（B 整体搬过来，与 A 环境融合）。

三图同改示例：
- `shape_from=B, fabric_from=C, color_from=A`：用 B 的轮廓，C 的材质，A 的颜色/环境。
- `shape_from=B, fabric_from=A, color_from=A`：把 B 的部件「本土化」到 A 上（本次 Stage 2 用法）。

#### ② 级联工作流

```
Stage 1:  A(马) ← B(猪嘴)        → out1.png
Stage 2:  A(牛) ← B=out1.png      → out2.png
```

每一步都是**独立确认书**，`image_b` 指向上一步输出。每步独立走 S0–S8，独立签①签②。

#### ③ 实测：猪嘴 → 马头 → 牛身（2026-09-14）

| 阶段 | 任务 | 来源路由 | 出图通道 | 结果 |
|---|---|---|---|---|
| Stage 1 | 猪嘴嫁接到马头 | shape=B, fabric=B, color=B | PUBLIC_OPENSOURCE（ImageGen）| ✅ 视觉成立，耳朵/眼睛/鬃毛未动 |
| Stage 2 | 马头（带猪鼻）嫁接到牛身 | shape=B, fabric=A, color=A | PUBLIC_OPENSOURCE（ImageGen）| ⚠️ 形状成立，颜色/纹理 FAIL |

闸门②实测数据：
- Stage 1：PASS 1/9，8 项 NOT_RUN（符合缺数据=NOT_RUN 铁律）。
- Stage 2：颜色 ΔE=21.18 **FAIL**，纹理方向角度差=9.4° **FAIL**。

**根因**：公开开源渠道（ImageGen）在 `shape_from=B, fabric/color_from=A` 时，
仍会部分保留 B 的颜色/材质，导致与 A 的周边环带不一致。

#### ④ 解药与迭代

1. **提示词强化（v4.1.0 已落地）**：`build_prompt_v2` 在混合来源时自动追加
   `Crucial: recolor/retexture the inserted part to match image A; do NOT keep the original color/material of the shape reference.`，
   明确约束模型不要照搬 B。
2. **本地通道优先**：Fooocus 的 inpaint + ControlNet 对 mask 内颜色/材质控制更精确；公开渠道作为兜底。
3. **后处理校色**：若形状已到位但颜色未跟上，可用 `hybrid_pipeline.py` 做曲线校色，
   再用 mask 把新增部件区排除在外，避免把好不容做出的结构又修回去。
4. **诚实记录**：闸门② FAIL 不是 bug，是技能按契约真实反馈。
   公开渠道版本应标注为「概念效果图」，本地通道版本才是「可交付零痕改图」。

#### ⑤ 给使用者的建议

- 级联任务每步独立确认、独立签①签②，不要把上一步的 NOT_RUN 带到下一步。
- 当 `fabric_from` 或 `color_from` 与 `shape_from` 不一致时，优先走**本地 GPU 通道**；
  公开渠道建议只拿第一版结构，再在校色轮修回。
- 若最终 闸门② 仍有 FAIL，**禁止签②交付**，必须修图或改确认项重出。

## 十、v3 比 v2 新增了什么（含 v3.1 / v3.2 / v3.3 / v3.4 补充）

1. **引擎可插拔注册表**——6 引擎登记，字段含多参考图/画幅跟随/水印/凭据/隐私/质量档
2. **数据分级路由**——`public`/`client`/`secret` 三档，涉密图禁出网
3. **火山方舟适配器**——凭据三级查找、小白向导、连通性测试、模型巡检、发布前泄漏自检
4. **★ 传统像素法通道**——纯色改色场景框外保真 99.89%，**完胜生成式引擎 750 倍**
5. **★ 引擎选择铁律**——按任务类型选（纯色改色→像素法；风格化/结构→生成式），不按引擎强弱选
6. **火山方舟三层关卡对照表**——401/404/429 各自含义与解药，避免混为一谈
7. **画幅跟随 + 水印门禁**——契约新增 9 字段（engine/render_size/aspect_error/watermark 等）
8. **`--engine` / `--privacy` 命令行参数**——点名引擎，缺凭据自动降级
9. **★ 组合拳流水线**（v3.1）——生成式出形 + 像素法校色，解决交付级色偏问题（−20→−3）
10. **连通域背景剔除**（v3.1）——像素法必须剔除背景误命中（实测 98% 候选在地板上）
11. **★ 移除部件专用打法**（v3.2，见 8.7）——**加部件和拆部件打法完全不同**：
    - 提示词必须**正向句式**（"no X"会被 Seedream 理解成"这里有个 X"；实测改动率 12.1%→22.4%）
    - 验收判据用**平整度（边缘强度比）**而非改动率（改动率会**假 FAIL**：细线像素占比小）
    - 必须**排除衣物固有结构线**（侧缝/公主线/腰省），否则误判成"残留"（实测误报 156%）
12. **移除任务三段式闭环**（v3.2）——正向出图 → 平整度点检 → 组合拳校色（实测色偏 −4.3→−0）
13. **★ 双动作与位置锚点**（v3.3，见 8.8）——"拆一处+加一处"同时做时：
    - 位置必须用**图上可见参照物做锚点**（腰头缝/原部件轮廓），禁用 upper/lower 模糊词
      （实测：模糊词→口袋落到大腿中部；锚点法→一次修正到位）
    - **色偏全局向量只能对齐一头** → 优先保主体，背景差异如实标注并给双版本
      （实测：裤身 −9.1→+1.5 对齐，背景 −3.4→+7.2 被连带）
    - **同材质同色检测的基准区必须光照相当**（跨明暗交界取样会误报色差 81）
14. **多动作任务迭代节奏**（v3.3）——结构→位置→校色，三轮闭环；
    锚点法写到位后可**压缩到两轮**（v3.4 PG-005 实测：斜插袋结构+位置一轮全对）
15. **★★ 亮度曲线校色**（v3.4，见 8.6 / 8.9）——修掉常数偏移的**结构性缺陷**：
    - Seedream 色偏是**非线性压暗**（暗部压得多、亮部压得少）→ 单一常数**只能对齐一头**
    - `--mode curve`（新默认）按像素亮度分箱查表：**最大区域偏差 17.3 → 4.7**
    - 关键：取样掩膜**收紧到衣身主体**（混入背景会拉偏曲线）+ **箱间平滑/插值**（否则出色带）
    - **`--exclude` 参数顺序校验**（v3.3 曾写反致静默失效，现已拦截报错）
16. **斜插袋（welt）提示词模板**（v3.4，见 8.9）——必须写明
    `an OPENING in the fabric, NOT a patch sewn on top`，否则会被做成"贴一块斜布"
17. **★ 引擎就绪判定修复**（v3.4）——`engine_registry.has_credential()` 原先**只查环境变量**，
    导致用 `--save` 把 Key 落盘到 `~/.workbuddy/ark_config.json` 后，引擎表仍报"❌缺凭据"，
    进而使 `choose_engine()` **误判 seedream 不可用并错误降级**（每次都降到低质量引擎）。
    已改为与环境变量并列检查用户配置文件，与 `ark_engine.load_credential` **同源**。
    > **排查心法**：`ark_engine.py --check` 与 `engine_registry.py` 的就绪结论**必须一致**，
    > 不一致就是判定逻辑分叉了 —— 两者都要读同一份凭据来源。
18. **★★ 三图同改 / 级联嫁接**（v4.1.0，见 8.10）——形状/材质/颜色可分别来自 A/B/C 三张图，
    上一步输出可作为下一步的 B。猪嘴→马头→牛身实测驱动了：
    - `sources{shape_from,fabric_from,color_from}` 独立路由
    - 混合来源提示词强化（防止公开渠道照搬 shape 参考图的颜色/材质）
    - 闸门② 诚实 FAIL 报告：Stage 2 颜色 ΔE=21.18、纹理角度差 9.4° 被正确拦截
    - `confirm.py` 改为懒加载 `python-docx`，`--ingest` 不再因缺 docx 而崩溃

> **v2 的历史贡献**：wearer_frame 镜像归一化、9 项前置确认、双签制、量化点检、
> 缺数据=NOT_RUN、GPU 三级探测、通道自适应。这些在 v3 中全部保留。
